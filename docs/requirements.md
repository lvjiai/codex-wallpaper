# 当前需求

1. Windows Codex 桌面端，个人使用，以插件管理。
2. 只保留应用内独立壁纸模式；已取消透明桌面模式。Codex 与桌面可以不同。
3. 自主选择多个 Wallpaper Engine Scene 并轮换。
4. Wallpaper Engine 的 Scene 必须由 WebWallGL 在应用内实时渲染，无需 Windows 捕获授权。
5. 文字、代码、输入控件保持独立不透明，正常点击、拖选、输入和滚动。
6. 后台辅助程序无任务栏或托盘图标；进入或恢复聊天后生效即可。
7. 不修改安装文件，不使用 DLL、远程线程或目标进程内存补丁。
8. 已批准本地页面 CDP、临时 JavaScript/CSS 背景层，以及带本机调试参数配置启动入口并重启。
9. 不接受整体 Alpha 让文字随窗口一起变淡的降级版本。

# 原型默认参数

场景目标 30 fps，使用窗口画布分辨率，默认每 300 秒顺序轮换。帧率、间隔和暗化可调整。

# 验收门槛

1. 当前 Codex 版本实际提供仅本机 CDP 页面连接。
2. 真实 Scene 持续渲染，画布像素签名随时间变化。
3. 画面显示在聊天后方，文字和输入框不继承背景 opacity。
4. 点击、拖选、滚动、输入法、缩放、最小化、恢复和退出正确；无遗留图标或抢焦点。
5. 单场景稳定后，再验收轮播、自动恢复和资源占用。

# 早期捕获实验记录

- 自动执行带调试参数启动 Codex，被审批返回 blocked by policy。未改用其他执行途径绕过；启动和恢复入口交由用户手动执行。
- WGC CreateForWindow 在普通和无边框测试 Scene 上均返回 E_ACCESSDENIED。读出的场景显示亲和性是 0，没有改动它，也未修改系统捕获隐私或权限设置。
- 标准系统选择器没有返回捕获项。尚不确定是取消、系统未授予，还是当前执行上下文限制；不能称为已经授权。
- 尚无实际 Scene 帧进入 Codex；协议测试不能代替端到端验收。

# 已停止的原生透明路线

顶层色键未改变画面；整体 Alpha 会使文字混入背景色。清除 WS_EX_NOREDIRECTIONBITMAP 没有受支持且完整可恢复的保证，色键还会改变透明像素的鼠标命中，因此已停止这一路线。
